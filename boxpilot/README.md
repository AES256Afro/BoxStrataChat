# BoxStrataChat: Strata on a Box

This repository is [AES256Afro's fork of Strata](https://github.com/AES256Afro/BoxStrataChat), the local LLM engine by
[niko1221](https://github.com/niko1221/strata). The fork exists for one reason: so Strata can be installed from the
[BoxPilot](https://github.com/AES256Afro/BoxPilot) app catalog like any other app, with **Qwen3.8-Flash-Next** set up as the
default model. The engine, the Terminal, the server and the desktop app are upstream's and are not changed here.

## What this fork adds

| File | What it is |
| --- | --- |
| [`boxpilot/strata.yaml`](strata.yaml) | The BoxPilot catalog manifest (schemaVersion 2). The copy that BoxPilot installs from lives at `catalog/strata.yaml` in the BoxPilot repository; this one is the source it is kept in step with. |
| [`.github/workflows/docker-images.yml`](../.github/workflows/docker-images.yml) | Upstream's image workflow, pointed at this fork's registry: it fetches the signed engine packages of an upstream release and publishes `ghcr.io/aes256afro/boxstratachat:<version>-<flavor>`. |
| [`docker/compose/docker-compose.boxstratachat.yml`](../docker/compose/docker-compose.boxstratachat.yml) | The same settings as the manifest, as a compose file, for a computer that is not a Box. |
| The banner at the top of [`README.md`](../README.md) | Says what this fork is and points here. |

Nothing else differs from upstream, so merging upstream is routine (below).

## How it gets onto a Box

1. The manifest is in BoxPilot's catalog (`catalog/strata.yaml`). It ships with the next BoxPilot release, and every Box that
   installs that release sees **Strata** under *Apps → AI*.
2. Installing it from the catalog creates a compose project `bp-strata` with the image, the `/data` volume, the port and the
   settings below. BoxPilot generates the API key and shows it on the app's card (there is no username).
3. The first start downloads Qwen3.8-Flash-Next into the data folder (66 to 76 GB for the ISTA-DASLab sizes) and prepares it. The
   container counts as installed once it has been running for a minute; the model is ready when the chat page answers. Watch
   the download under *Logs*.
4. The server answers at `http://<the box>:8111`: the chat page at `/`, the OpenAI-style API at `/v1` and the Anthropic-style
   API at the root, every request with `Authorization: Bearer <the API key>`. `GET /v1/models` lists the model name.

### What a Box needs

Strata's engine runs on a graphics card only. There is no CPU engine, so on a Box without one the container starts, says in
plain words that the engine does not match the computer's card, and stops; BoxPilot then puts the install back.

| | Needed |
| --- | --- |
| Card | NVIDIA RTX 20, 30, 40 or 50 series (the `cuda13` image), driver 580 or newer, the NVIDIA Container Toolkit set up for Docker (BoxPilot's Repair Center shows the state). GTX 10 / Pascal cards and drivers 575 to 579 need the `cuda12` image instead: change the image in the manifest. AMD and Intel cards have their own images (`rocm-gfx120x`, `rocm-gfx110x`, `rocm-gfx1151`, `sycl`); see upstream's [docs/DOCKER.md](../docs/DOCKER.md). |
| Memory | RAM plus VRAM for the model: Q2_0 37.6 GB, IQ2_XS 39.2 GB, IQ3_XXS 47 GB (the default), IQ3_S 54.8 GB. |
| Disk | 66 to 76 GB free in the data folder for the download (about 76 GB for the default IQ3_XXS), plus room for the prepared pack. |

## Settings the catalog offers

These are the manifest's settings; each is one of the image's environment variables ([docs/DOCKER.md, Settings](../docs/DOCKER.md#settings)).

| Setting | Variable | Default | Choices |
| --- | --- | --- | --- |
| Model family | `FAMILY` | `qwen` (the ISTA-DASLab Qwen3.8-Flash-Next originals) | `unsloth` (4 to 8 bit files, 72 to 136 GB), `gyro` (least memory, slower), `coder` (coding-only, about 32 GB), `swift` (the Swift 1.5 fine-tune, thinks shorter) |
| Model size | `MODEL` | `IQ3_XXS` | qwen and swift: `Q2_0`, `IQ2_XS`, `IQ3_XXS`, `IQ3_S`; unsloth: `UD-IQ4_XS`, `UD-Q4_K_XL`, `UD-Q5_K_XL`, `UD-Q6_K_XL`, `Q8_0`; gyro: `Gyro-S`, `Gyro-M`; coder: `IQ1_M`; any case; empty lets Strata pick for the card |
| Context length | `CONTEXT` | `32k` | `64k`, `128k` |
| Requests answered at once | `PARALLEL` | `1` | 1 to 8 |
| Read pictures | `VISION` | `off` | `on` (0.9 GB more to download) |
| Tune on first start | `TUNE` | `skip` | `quick` (up to about 20 minutes, once) |
| Model files you already have | `MODEL_PATH` | empty (download) | `/models`, with the optional GGUF folder pointed at a folder holding one model's shards |
| API key | `API_KEY` | generated by BoxPilot | |

Fixed: `PORT=8080` inside the container (published as 8111), `PRESET=boxpilot`, `shm_size` 2 GB, and a two-minute stop
grace period (`stopGracePeriod: 2m`, a manifest field added to BoxPilot for this app) so the engine can unload the model
before Docker kills it. BoxPilot's compose has no `memlock` ulimit, so the engine cannot pin its RAM; it warns in the log
and runs anyway.

## Images

The manifest pins **upstream's** published image, `ghcr.io/niko1221/strata:0.2.12-cuda13`, by digest. It is public and
pullable today, which BoxPilot's catalog rule requires before a manifest lands.

This fork's own images come from the *Docker images* workflow (Actions tab → Docker images → Run workflow). It is run by
hand, takes an upstream release tag (for example `v0.2.12`), downloads that release's engine packages, checks them against
the signed update feed, builds each flavor with `docker/build.sh` and, with *push* on, publishes
`ghcr.io/aes256afro/boxstratachat:<version>-<flavor>` and `latest-<flavor>`. To move the catalog to them:

1. Run the workflow with *push* on. The first push creates the GHCR package **private**.
2. Make the package public in its own settings (Package → Settings → Danger Zone → Change visibility). There is no API for this;
   BoxPilot's `catalog-check-images` reports a private package as `MISSING`, and no Box could install it.
3. In BoxPilot, change `image.reference` in `catalog/strata.yaml` to `ghcr.io/aes256afro/boxstratachat:<version>-cuda13` and
   `image.version` to match, run `node scripts/catalog-pin-digests.mjs --write` to pin the digest, and copy the result back to
   `boxpilot/strata.yaml` here.

## Keeping up with upstream

```sh
git remote add upstream https://github.com/niko1221/strata.git   # once
git fetch upstream
git merge upstream/main
```

The only files that can conflict are the four listed above. After a merge, check that `.github/workflows/docker-images.yml`
still names `ghcr.io/aes256afro/boxstratachat`, that the README banner is still at the top, and whether the manifest's
image version should move to the new release (then re-pin it in BoxPilot).

## Checking a manifest change

In the BoxPilot repository:

```sh
npx vitest run server/catalog/catalog.test.mjs server/catalog-install-smoke.test.mjs
node scripts/catalog-check-images.mjs
```

The first validates the manifest and installs it against a fake Docker; the second asks the registry that the pinned tag
still exists and points at the pinned digest.
